Deep Agents

복잡한 장기 태스크를 처리하기 위해 설계된 에이전트 하니스(harness). Planning, SubAgent, FileSystem, Prompt의 4대 요소로 Shallow Agent의 한계를 돌파한다.

❓ Why Deep Agents?

Shallow Agent의 구조적 한계와 Deep Agent가 제시하는 해결 방법

⚠️ Shallow Agent의 근본 문제

Shallow Agent는 5~15단계 태스크에 적합하지만, 500단계 이상의 복잡한 작업에서는 컨텍스트 오버플로우, 목표 상실, 복구 불능으로 실패한다.

🔻 Shallow Agent의 한계

  • 단일 컨텍스트 윈도우에 모든 정보를 축적 → 토큰 한계 도달 시 성능 급락
  • 계획 없이 실행 → 중간 단계에서 원래 목표를 잃어버림
  • 자기 검증 부재 → 자신이 작성한 코드를 다시 읽고 "OK" 판단 후 종료
  • 복구 메커니즘 없음 → 토끼굴에 빠지면 무한 루프 또는 포기
  • 단일 에이전트 실행 → 모든 도메인을 하나의 프롬프트로 처리

🔺 Deep Agent의 해결 전략

  • 외부 파일시스템으로 컨텍스트 오프로드 → "모든 것을 기억" → "어디서 찾을지 안다"
  • Todo List Planning → 작업 분해, 진행 추적, 목표 유지
  • 검증 루프 내장 → PreCompletionChecklist로 종료 전 자동 검증
  • 자동 요약 → 80K 문자 초과 시 히스토리를 요약·오프로드
  • 서브 에이전트 위임 → 특화된 에이전트에 격리된 컨텍스트로 위임
항목 Shallow Agent Deep Agent
실행 범위 5~15 스텝 수백 스텝, 수 시간
컨텍스트 관리 단일 윈도우 축적 파일시스템 + 자동 요약
계획 수립 없음 (즉흥 실행) Todo 기반 계획·추적
에이전트 구조 단일 에이전트 메인 + 서브에이전트 계층
검증 자기 확인 → 종료 검증 루프 → 수정 → 완료
메모리 대화 내 한정 크로스 세션 영속 메모리
프롬프트 단순 지시 상세 시스템 프롬프트 + Few-shot

🧩 4대 핵심 개념

Deep Agent를 구성하는 네 가지 필수 요소

Planning — 계획 수립 도구

write_todos 도구를 통해 복잡한 태스크를 이산적 단계로 분해하고, 진행 상황을 추적하며, 새로운 정보에 따라 계획을 적응시킨다.

💡 핵심 인사이트

write_todos는 실제로 아무 로직도 실행하지 않는 no-op 도구다. 이것은 컨텍스트 엔지니어링 전략으로, 에이전트가 계획을 명시적으로 작성함으로써 목표에 집중하도록 유도하는 장치이다.

# write_todos 사용 예시
agent.invoke({
    "messages": [{
        "role": "user",
        "content": "OAuth2 인증 시스템을 구현해줘"
    }]
})

# 에이전트 내부 동작:
# 1. write_todos 호출 → 계획 수립
#    - [ ] OAuth2 라이브러리 조사
#    - [ ] 데이터 모델 설계
#    - [ ] 인증 엔드포인트 구현
#    - [ ] 토큰 갱신 로직 구현
#    - [ ] 테스트 코드 작성
# 2. 각 단계를 순차 실행하며 완료 표시
# 3. 새로운 정보 발견 시 계획 재조정

SubAgents — 태스크 위임

task 도구로 특화된 서브에이전트를 생성하여 독립적 컨텍스트에서 하위 태스크를 수행시킨다. 메인 에이전트의 컨텍스트를 깨끗하게 유지하면서도 깊이 있는 작업이 가능하다.

🎯 컨텍스트 격리

각 서브에이전트는 독립된 컨텍스트 윈도우에서 동작. 메인 에이전트에 합성된 결과만 반환.

🔄 재귀적 위임

서브에이전트가 다시 서브에이전트를 생성 가능. 복잡한 태스크를 트리 구조로 분해.

📂 파일시스템 공유

모든 에이전트가 동일 파일시스템에 접근. 파일을 통한 결과 교환 및 협업.

# 서브에이전트 위임 예시
# 메인 에이전트가 내부적으로 task 도구 호출:
task(
    description="FastAPI OAuth2 엔드포인트 구현",
    # 서브에이전트는 격리된 컨텍스트에서 실행
    # 결과는 파일시스템에 저장 후 요약만 반환
)

FileSystem — 외부 메모리

가상 파일시스템을 통해 컨텍스트 윈도우 외부에 정보를 저장·검색한다. "모든 것을 기억"에서 "어디서 찾을지 안다"로 패러다임을 전환하는 핵심 요소.

내장 파일시스템 도구 (6개)

도구용도시그니처
ls디렉토리 탐색ls(path)
read_file파일 읽기read_file(path, start_line, end_line)
write_file파일 쓰기write_file(path, content)
edit_file라인 기반 수정edit_file(path, edits)
glob패턴 검색glob(pattern)
grep내용 검색grep(pattern, path)

Prompt — 상세 시스템 프롬프트

Deep Agent의 시스템 프롬프트는 단순 지시문이 아닌, 도구 사용법, 행동 규칙, Few-shot 예시를 포함한 종합 매뉴얼이다. Claude Code의 재현 시스템 프롬프트가 대표적 사례.

📚 도구 사용 가이드

각 도구의 정확한 사용법, 파라미터 설명, 사용 시점 지침을 상세히 기술.

🎭 Few-shot 예시

다양한 시나리오에서의 올바른 행동 패턴을 구체적 예시로 제공.

🚧 경계 조건 명시

해야 할 것과 하지 말아야 할 것을 명확히 규정하여 에이전트 행동 범위 설정.

🧠 추론 가이드

"Reasoning Sandwich" — 계획 시 Extra-High, 실행 시 High, 검증 시 Extra-High 추론 예산 배분.

create_deep_agent() 팩토리

Deep Agents의 진입점. 미들웨어 스택을 조립하고, 기본 백엔드를 설정하며, LangGraph CompiledStateGraph를 반환한다.

from deepagents import create_deep_agent
from langchain.chat_models import init_chat_model

# 최소 설정 — 2줄로 에이전트 생성
agent = create_deep_agent()

# 커스텀 설정
agent = create_deep_agent(
    model=init_chat_model("anthropic:claude-sonnet-4-20250514"),
    tools=[my_custom_tool],         # 추가 도구
    system_prompt="You are ...",    # 커스텀 프롬프트
    backend=my_backend,             # 커스텀 백엔드
    middleware=[my_middleware],      # 추가 미들웨어
)

# 반환값: CompiledStateGraph
# → invoke(), stream(), astream() 모두 지원
result = agent.invoke({
    "messages": [{"role": "user", "content": "..."}]
})

BackendProtocol 인터페이스

모든 상태 기반 연산이 경유하는 추상 계층. 백엔드를 교체하는 것만으로 실행 환경을 전환할 수 있다.

class BackendProtocol(Protocol):
    """모든 백엔드가 구현해야 하는 인터페이스"""

    def read(self, path: str) -> str:
        """파일 읽기"""
        ...

    def write(self, path: str, content: str) -> None:
        """파일 쓰기"""
        ...

    def ls_info(self, path: str) -> dict:
        """디렉토리 정보 조회"""
        ...

    def execute(self, command: str, cwd: str = None) -> dict:
        """셸 명령 실행"""
        ...

AgentMiddleware 프로토콜

미들웨어는 에이전트 실행의 각 단계에 훅을 걸 수 있는 4개 메서드를 제공한다.

Hook시점용도
before_agent() 에이전트 시작 시 1회 상태 초기화 (메모리 로드, 환경 탐지)
wrap_model_call() 매 LLM 호출마다 도구 주입, 컨텍스트 압축, 프롬프트 캐싱
before_tool_call() 도구 실행 전 HITL 승인, 인자 검증, 로깅
after_tool_call() 도구 실행 후 결과 오프로드, 루프 감지, 후처리

팩토리 조립 과정

🔗 미들웨어 시스템

Core SDK와 CLI에 포함된 미들웨어 파이프라인 상세

Core SDK 미들웨어 스택

고정된 순서로 조립되며, 각 미들웨어가 에이전트의 행동을 보강한다.

📋 TodoListMiddleware
write_todos 도구를 주입. 태스크 분해, 진행 추적, 계획 적응을 담당. 실제 로직 없는 no-op 도구이지만, 에이전트의 계획적 사고를 유도하는 컨텍스트 엔지니어링 장치.
📁 FilesystemMiddleware
6개 파일 도구 주입 (ls, read_file, write_file, edit_file, glob, grep). 80K 문자 초과 도구 결과를 /large_tool_results/에 오프로드하고, 대화 히스토리의 도구 인자를 자동 축약하여 토큰 절약.
🤖 SubAgentMiddleware
task 도구를 주입. 격리된 컨텍스트에서 서브에이전트를 생성·실행하고, 합성된 결과만 메인 에이전트에 반환. 재귀적 서브에이전트 생성 지원.
📝 SummarizationMiddleware
총 컨텍스트가 ~80,000자 초과 시 작동. 대화 히스토리를 /offloaded_history/에 저장하고 요약으로 교체. compact_conversation() 수동 호출도 지원.

CLI 확장 미들웨어

CLI 패키지에서 Core 스택 위에 추가되는 미들웨어.

⚙️ ConfigurableModelMiddleware

런타임에 모델 동적 전환. 태스크 복잡도에 따라 모델 등급 조절.

❓ AskUserMiddleware

에이전트가 사용자에게 인터랙티브 질문. 불확실한 상황에서 판단 위임.

📍 LocalContextMiddleware

시작 시 Git 저장소, 패키지 매니저 등 로컬 환경 자동 탐지 및 컨텍스트 주입.

✋ HITLMiddleware

Human-in-the-Loop. 위험한 도구 호출 전 사용자 승인 요청. 세션별 허용 목록 관리.

🧠 MemoryMiddleware

AGENTS.md 파일을 로드하여 시스템 프롬프트에 주입. 크로스 스레드 영속 메모리.

🎯 SkillsMiddleware

SKILL.md 파일을 점진적 공개(progressive disclosure) 방식으로 로드. 태스크 관련 스킬만 활성화.

Harness Engineering 고급 미들웨어

🔍 PreCompletionChecklistMiddleware

에이전트 종료 전에 가로채서 태스크 명세 대비 검증 패스를 강제 실행. 에이전트가 자기 코드를 읽고 "OK" 판단 후 조기 종료하는 문제를 방지.

# 검증 4단계 사이클:
# 1. Planning & Discovery — 태스크 분석, 코드베이스 스캔
# 2. Build — 테스트 우선 구현
# 3. Verify — 테스트 실행, 명세 대비 확인
# 4. Fix — 오류 분석 및 반복
🔄 LoopDetectionMiddleware

파일별 편집 횟수를 추적하여 N회 편집 후 접근 방식 재고를 제안. "Doom Loop" 방지.

🧪 LangSmith Trace Analyzer

실험 트레이스를 자동 수집, 병렬 에러 분석 에이전트를 생성하여, 발견된 패턴을 하니스 수정으로 변환. ML의 부스팅 기법과 유사한 접근.

발견되는 주요 실패 패턴: 추론 오류, 지시 미준수, 테스트 미실행, 타임아웃.

🫡 Ralph Mode — 무한 반복 실행

에이전트를 매 반복마다 새로운 컨텍스트로 실행하되, 파일시스템을 메모리로 사용하여 연속성을 유지하는 패턴. 시작 후 중단(Ctrl+C)할 때까지 자율적으로 실행.

HEIBO는 이미 Reflexion, ToolRegistry, 벡터 검색 등 Deep Agents의 핵심 패턴을 상당 부분 구현하고 있음. 컨텍스트 오프로드와 히스토리 요약을 우선 적용하면 장기 대화 시 토큰 비용과 응답 품질을 동시에 개선할 수 있음. 미들웨어 훅 계층은 파이프라인 확장 시점에 도입하는 것이 효율적.

💡 시사점

Deep Agents가 에이전트 엔지니어링에 미치는 영향과 실무 적용 패턴

1

Harness > Model

모델 성능보다 하니스 엔지니어링이 결과를 좌우한다. 같은 모델이라도 프롬프트, 미들웨어, 검증 루프 설계에 따라 13%p 이상 차이.

2

Context = FileSystem

"모든 것을 기억"에서 "어디서 찾을지 안다"로 전환. 파일시스템이 에이전트의 외부 메모리이자 협업 공간.

3

Planning = No-Op

계획 도구가 실제 로직을 실행하지 않아도 효과적. 컨텍스트 엔지니어링으로서의 계획이 핵심.

4

검증이 완성한다

에이전트의 자기 검증은 불충분. PreCompletionChecklist와 LoopDetection으로 외부 검증을 강제해야 한다.

5

보안은 도구 계층에서

"Trust the LLM, enforce at tool layer." 모델의 자기 검열에 의존하지 말고, 백엔드/샌드박스 수준에서 경계 설정.
